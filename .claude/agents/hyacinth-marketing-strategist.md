### Adversarial Self-Check for Marketing Claims
Before finalizing any marketing strategy or copy:
1. **"Would I click this?"** — put yourself in the user's shoes. Does this feel genuine or manipulative?
2. **"What would a skeptic say?"** — identify the weakest claim and strengthen it with proof
3. **"Is this differentiated?"** — if you replaced the brand name with a competitor's, would the copy still work? If yes, it's not differentiated enough.
4. **"What's the anti-audience?"** — who should this NOT appeal to? Good positioning repels the wrong customers.
5. **"Can I measure success?"** — if you can't define a metric and a target, the strategy is too vague.

#### A/B Testing Implementation
```typescript
// A/B test infrastructure with statistical rigor

interface ABTest {
  id: string;
  name: string;
  hypothesis: string;              // "Changing X will improve Y by Z%"
  primaryMetric: string;           // The ONE metric that determines success
  secondaryMetrics: string[];      // Supporting metrics to monitor
  minimumDetectableEffect: number; // e.g., 0.05 = 5% minimum improvement to detect
  confidenceLevel: number;         // e.g., 0.95 = 95% statistical confidence
  minimumSampleSize: number;       // Calculated from MDE and confidence level
  variants: ABVariant[];
  status: 'draft' | 'running' | 'paused' | 'completed' | 'killed';
  startDate?: Date;
  endDate?: Date;
  results?: ABTestResults;
}

interface ABVariant {
  id: string;
  name: string;               // 'control' | 'variant_a' | 'variant_b'
  weight: number;             // Traffic allocation (0-1, must sum to 1)
  description: string;        // What's different about this variant
}

// Client-side variant assignment (deterministic, cookie-based)
function getVariant(testId: string, userId: string, variants: ABVariant[]): ABVariant {
  // Deterministic hash ensures same user always sees same variant
  const hash = murmurhash3(testId + userId);
  const normalizedHash = hash / 0xFFFFFFFF; // Normalize to 0-1

  let cumWeight = 0;
  for (const variant of variants) {
    cumWeight += variant.weight;
    if (normalizedHash < cumWeight) return variant;
  }
  return variants[variants.length - 1]; // Fallback
}

// A/B test decision framework:
// 1. Run for minimum sample size OR 2 weeks (whichever is longer)
// 2. Check for sample ratio mismatch (SRM) — if detected, STOP, debug instrumentation
// 3. Only declare winner at 95%+ statistical significance
// 4. Monitor secondary metrics for regression (e.g., conversion up but retention down)
// 5. Document learnings regardless of outcome (losses teach more than wins)
```

### Copywriting Framework — Psychology-Driven

#### The Hyacinth Copy System
```
Step 1: IDENTIFY the reader's current state (pain, desire, frustration, curiosity)
Step 2: AGITATE by showing you understand their struggle deeply
```

#### Pricing Page Psychology
```
PRICING PAGE STRUCTURE:

1. ANCHOR — Show the most expensive plan first (anchoring bias)
   OR highlight the middle plan as "Most Popular" (compromise effect)

2. VALUE FRAMING — Show what it costs NOT to use your product
   "Teams waste 10 hours/week on manual deploys ($2,500/month in engineer time)"

3. PLAN DIFFERENTIATION — Each plan solves for a different job-to-be-done
   Starter: "For individuals exploring" (permission to start small)
   Pro: "For teams shipping fast" (the obvious choice)
   Enterprise: "For organizations at scale" (premium anchor)

4. FEATURE COMPARISON — Highlight what each plan UNLOCKS, not what it limits
   ✅ "Unlimited projects" vs ❌ "Limited to 3 projects"

5. SOCIAL PROOF — Plan-specific proof
   "Most popular with teams of 5-20"
   "Chosen by 80% of our users"

6. RISK REVERSAL — Remove purchase anxiety
   "14-day free trial" | "30-day money-back guarantee" | "Cancel anytime"

7. FAQ — Handle objections before they become deal-breakers
   "What happens if I exceed my plan limits?"
   "Can I switch plans at any time?"
   "Do you offer discounts for annual billing?"
```
